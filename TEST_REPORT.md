## Evidence and known limits

Browser results: `tests/.runtime/ui/browser-results.json`; screenshots: `dashboard-light-desktop.png`, `dashboard-dark-desktop.png`, `dashboard-dark-mobile.png`, `native-editor-desktop.png`, `native-editor-mobile.png` in the same directory. Browser data is synthetic, not production telemetry.

Final verified sequence 83; RX=1058170518, TX=58964800, both=1117135318 bytes; pending=0. Test services were stopped and disabled after verification; VM test data/config remain for inspection. No production source fixes were necessary; v2.0.0 code is unchanged, only verification tooling/reporting and packaged documentation were supplemented.

Initial verification fixed non-root PID1 namespace access, retry behavior after plugin disable, reporting-thread failure detection, a real mobile drawer overlay/touch-scroll restriction, and the reset-state distinction between unknown usage and preserved history. All affected suites were rerun. A DST test's initially incorrect hard-coded reference timestamp was replaced by explicit offset-aware date conversion; the independent allocation comparison then passed.

Already sampled/committed data survives restart and can be resent idempotently. Unobserved bytes immediately before sudden power loss cannot be recovered; new interface generations establish baselines rather than inventing history. Cross-day placement is integer-conserving interval proration, not packet-level timing. Explicit non-overlapping interface selection and correct host network namespace remain deployment responsibilities. See README and collector README for installation, backup and recovery boundaries.
